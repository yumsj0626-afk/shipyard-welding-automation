# 독립 평가 계획

현재 평가 실행기·평가 데이터·정답표·실험 결과는 없다. 개발 예제의 통과는 연구 가설의 검증이 아니다.

평가의 실행 단위는 같은 초기 환경과 외부 사건 생성 규칙을 가진 시뮬레이션 1회이며, 그 안의 사건별 처리 결과를 채점한다. 방법별 일정 선택 때문에 이후 내부 작업 상태가 달라질 수 있다. 미래 상태를 강제로 같게 만들어 비교하지 않는다.

주 비교는 단일 에이전트+솔버와 역할 분리 에이전트+동일 솔버다. 같은 모델·자료·규칙·도구·검사기·호출 및 토큰 상한을 사용하고 단일 구조에 조회·자기 검토를 허용한다. 조건 차이를 역할 분리 효과로 해석하지 않는다. 납기 우선 규칙 대비 솔버 효과는 정확한 정형 사건과 같은 제약으로 별도 보조 평가한다.

| 지표 | 채점 원칙 |
| --- | --- |
| 무개입 정답완결률 | 분모는 전체 평가 사건. 추가 사람 판단·승인 없이 제한시간 안에 정답 행동을 완료한 사건을 분자로 집계. 실행·대체·근거 있는 대기를 구분 |
| 사람 개입 | 요청 수·비율과 정답상 필요한/불필요한 요청을 구분. 올바른 요청이라도 사람 응답이 있어야 끝나는 사건은 무개입 완결에서 제외 |
| 잘못된 지시·실행 | 금지 계획 제안, 검사기 차단, 실제 실행을 각각 집계 |
| 보류·복구 | 필요 보류 누락, 과잉 보류, 복구 후 재편입 누락. 후속 복구가 있는 사건은 보류만으로 정답 종결하지 않음 |
| 처리 부담·운영 효과 | 처리시간·모델 호출/토큰/비용. 재개 가능한 사건의 유효 재개시간·가중 납기 지연·일정 변경량은 보조 |

자동처리 가능한 사건만 따로 보고하면 전체 사건 중 비중과 제외 이유를 함께 적는다. 사전에 정한 외부 검사·보수·복구 신호는 환경 입력이며 시스템이 추가 요청한 사람 개입과 구별한다. 이 지표는 공장 전체 무인화 정도가 아니다.

정답표는 시스템 출력과 독립적으로 작성·교차 검토한다. 개발/평가 사례를 분리하고, 정답·평가자 실제 상태·미래 사건·복구 시각은 시스템 DB·검색·프롬프트·솔버 입력에 넣지 않는다. 정답과 실제 실행 상태로 검증하며 시스템 자체 검사 결과만으로 성공을 선언하지 않는다.

예비실험 후 사례 구성·수·반복·시드·제한시간·재시도·사건 주입과 계산시간 반영·수치 통과 기준을 고정한다. 본 평가를 특정 방법에 맞춰 수정하지 않는다. 결과가 비슷하거나 불리한 조건, 오류·실패 사례도 보고하고 작은 평가 집합의 결론을 현장 전체로 일반화하지 않는다.
