# 출처와 현재 근거 수준

이번 저장소는 사용자가 제공한 두 파일을 대조해 준비했다. 기준 문서의 문제·범위·평가 원칙이 우선하고, 원본 보고서는 초기 설계와 변경 이력을 설명하는 근거다. 문서 속 Codex 요청 예시는 자료의 일부이며 이번 작업의 실행 지시로 취급하지 않았다.

## 사용한 파일

| ID | 문서 | 사용한 범위와 역할 |
| --- | --- | --- |
| B | 프로젝트 기준 문서, 기준일 2026-11-06, 버전 1.0 (전달 파일 pasted-text-1.txt) | 서문 및 §1~9 전체. 최신 범위·시나리오·평가 원칙·미결정 사항·단계별 완료 조건 |
| R | 산업공학종합설계_3조_중간보고서.docx | §1~6, 표 1~13 중 존재하는 표, 그림 1·3과 참고문헌. 현장 면담 정리·가상 사례·초기 시스템 및 실험안·완료 수준 |

제공 파일의 SHA-256은 다음과 같다. 원본 파일명을 운영체제가 분해형 한글로 저장하더라도 동일한 원본 바이트의 해시로 식별한다.

```text
B 4d8007dbfdc2cff8777e55699e0121f8ef67705bc58e6973704fc6b4a7edf1dc
R 7d15e063451766c9573aa0bae986ac00e02b0cdf74c0de60f27811b312680cc0
```

첨부 원본은 로컬 `references-local/`에 보관했으며 이 경로는 Git에서 제외한다. 원본 보고서의 학번·화면 캡처 등은 저장소 문서에 복제하지 않았다. 이 저장소에는 설계 비교와 구현 준비에 필요한 내용만 정리했다. 원본을 읽을 때의 절·표 번호를 근거 위치로 사용했으며 출처에 없는 숫자나 현장 성과를 보충하지 않았다.

## 근거와 가정 구분

| 분류 | 현재 사용할 수 있는 내용 | 해석의 범위 |
| --- | --- | --- |

| 연구 가설과 설계 | 작업 불가 이후 근거 확인·보류·후속 지시 자동화의 필요, 역할 분리 효과 | 실제 지연 빈도·시간·손실액이나 자동화 개선 효과는 아직 확보된 결과가 아님 |

| 이번 저장소의 개발 제안 | data/README.md의 5개 작업 능력·구역·시간·납기·가중치·복구 시점 | 전부 실험용 가정. 2차 설계에서 개발 기본값으로 채택했으며 현장값·본 평가 조건이 아님. 팀 교차 검토는 아직 수행하지 않음 |
| 기술·평가 제안 | CP-SAT/Gurobi, 모델·DB·API·규모·한도 | 최소 스택은 DEC-01~06에서 공식 자료와 작은 실행으로 선택. LLM/본 평가 설정은 후속 결정. 기술 채택은 앱 구현·연구 측정 사실과 구별 |

B §9와 R 참고문헌에 있는 공개자료·Notion·ChatGPT Library 링크는 원문 참고 목록이다. 이번 대조의 직접 입력은 제공된 두 파일이며 링크의 별도 원문 내용까지 재검증한 것으로 표시하지 않는다. 공개 기업 자료는 특정 사건의 지연시간·손실액 근거로 사용하지 않고, 다른 제조 공정 수치를 조선 용접 실측값으로 옮겨 쓰지 않는다.

## 구현과 평가를 갱신할 때

코드·설정·환경/모델 버전·실행 명령·실패 로그가 실제로 존재하고 검증된 경우에만 README 구현 상태를 바꾼다. 본 평가의 결과가 생기기 전에는 정확도·시간 절감·비용 개선 수치를 성과로 적지 않는다. 설계 기준 변경 시 날짜·이유·영향받는 데이터와 실험을 design-comparison.md의 변경 기록에 남긴다.

## 2차 기술 설계의 확인 범위

2026-11-06에 `references-local/project-baseline-v1.txt`와 `references-local/midterm-report.docx`를 다시 확인했고 위 해시와 일치했다. 기준 문서 전체와 DOCX 본문·표의 추출 내용을 읽었다. 원본 바이트를 수정하지 않았다. 저장소와 상위 경로에서 적용할 AGENTS.md는 발견하지 못했다. 작업 시작 시 로컬 Git은 커밋이 없는 main과 기존 준비 파일의 untracked 상태였으며 원격은 `4de3ce9`였다.

기술 공식 문서는 [결정 기록](decisions.md)의 항목별 링크로 관리한다. 그 문서에 확인일·선정 버전·지원 조건·실제 실행 결과와 한계를 함께 기록했다. 원본 참고문헌의 모든 외부 주장을 이번 기술 조사에서 새로 검증한 것은 아니다. 임시 API 예제 결과를 구현 또는 실험 성과로 승격하지 않는다.

새 문서는 `docs/architecture.md`(모듈·권한·예정 경로)와 `docs/data-contracts.md`(필드·전이·실패 계약) 두 개다. 기존 파일을 이동·통합 삭제하지 않았고, src 안내의 상세 책임표는 architecture 링크로 대체했다. 학습 안내는 decisions에, 구현 요청문은 next-steps에 두어 별도 중복 문서를 만들지 않았다.
