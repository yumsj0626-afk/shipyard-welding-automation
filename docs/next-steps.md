# 다음 작업의 순서와 완료 기준

이번 변경은 저장소 준비까지다. 아래 항목은 모두 **미착수**이며 다음 작업의 실행 목록이다. 목표는 정형 사건의 자동 처리 흐름을 로봇 2대·작업 5개에서 재현하는 것이다. 문장형 보고·에이전트 비교는 그 다음 단계다.

## 작업 순서

| 순서 | 작업과 선행조건 | 산출물 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 범위·근거·개발 사례 정리 | 출처/추정/실험용 가정표, 사건별 규칙, 독립 정답표 초안 | [개발 사례](../data/README.md)의 각 수치가 가정임을 표시. 핏업과 조합 제한, W17 복구와 W20 착수 조건을 다른 팀원이 같은 근거로 설명하고 교차 검토 기록을 남김 |
| 2 | 최소 구현에 필요한 기술·계약 결정. 1 이후 | DEC-01~06의 구현 필수 부분, 상태/사건/계획/검사/로그 형식, 설치·실행 방법 초안 | CP-SAT/Gurobi 선택 근거와 팀 재현 조건 확인. 필수 필드·시간 단위·버전·중복·실패 종류·자동 적용 조건을 기록. 미정인 본 평가 수치와 분리 |
| 3 | 상태와 사건 검사. 2 이후 | 초기화·조회·코드에 의한 갱신, 정형 사건 검사, 활성 제한 목록과 근거 연결 | 대상·종류·시점·출처·근거·버전 검사. 누락·불일치 입력이 실행을 허용하지 않음. 같은 사건을 재전달해도 상태 변화가 중복되지 않고 충돌하는 같은 ID는 구별 |
| 4 | 고정 규칙의 제약 변환. 3 이후 | 보류/선행차단/조합금지/가용성·구역 제한 변환 | 핏업 W17을 어느 로봇도 수행하지 못함. W20의 선행조건 유지. R1–W17만 불가인 별도 사례에서 다른 조합까지 막지 않음. 진행 작업 유지 |
| 5 | 솔버 연결. 4 이후 | 배정·순서·시작/완료 계산, 해 상태·목적값·계산시간 기록 | 보류·능력·선행·로봇/구역 중복·이동/준비·진행 중 고정 반영. 대체 후보 여럿과 후보 없음 모두 처리. 해 없음·시간 내 미발견·실행 가능/최적성 미증명을 구별 |
| 6 | 독립 실행 검사와 적용. 5 이후 | 솔버와 별도로 작성한 제약 검사, 최신 상태·계획 버전 확인, 코드에 의한 적용 | 일부러 잘못 만든 계획을 각 제약에서 차단. 계산 중 상태가 바뀐 계획은 적용되지 않음. 검사와 적용 사이 상태 변경도 검사/적용 계약으로 차단. 재전송이 중복 착수를 만들지 않음 |
| 7 | 경량 시뮬레이터·외부 신호·로그. 6 이후 | 사건 주입, 시간 진행, 실제 시작/완료, 외부 복구 신호, 전체 처리 기록 | 이미 시작한 W18이 유지됨. 실제 완료 상태가 선행조건 판단에 반영됨. W17 조치 완료+재확인 후 재편입, W20은 W17 실제 완료 후 시작. 외부 미래 시각은 계획기에 전달되지 않음 |
| 8 | 개발 통합 검증과 사용 안내. 7 이후 | 개발 사례 실행 결과, 독립 채점 결과, 실패 로그, 정확한 재현 명령·환경 버전 | 아래 완료 기준을 만족하고 새 환경에서 같은 사건 흐름을 재현. 명령·시드/설정·제약/검사 결과·잔여 실패를 기록. README 상태를 실제 구현 수준만큼 갱신 |

실제 담당·마감은 아직 정하지 않았다. 개발 중 통합 오류를 발견하면 바로 전 단계의 계약과 사례를 수정하고 변경 이유를 남긴다. 새로운 구현 요청 없이 이번 저장소 준비에서 위 작업을 실행하지 않는다.

## 최소 흐름의 수락 기준

다음은 개발 검증 항목이며 연구 성능 목표나 본 평가 표본이 아니다. 특정 최적 일정 한 가지에 맞추지 않고 허용 행동과 제약으로 판정한다.

| ID | 사건/검증 | 관측 가능한 완료 기준 |
| --- | --- | --- |
| M01 | 정상 초기화 | R1·R2와 W17~W21을 읽고 미착수·진행·완료를 구별. 이미 진행 중인 W18의 배정·완료 예정은 재계획으로 바뀌지 않음 |
| M02 | 핏업 불가 | W17이 모든 로봇에서 보류되고 W20 착수가 막힘. 무관한 가능 작업을 일괄 보류하지 않음 |
| M03 | 대체 후보 있음 | 능력·준비·선행·구역·이동/준비시간을 반영한 계획이 별도 검사 후 승인 요청 없이 적용되고 대체 작업이 실제 시작·완료됨. 가능한 대체가 있는데 이유 없이 전부 정지하면 실패 |
| M04 | 대체 후보 없음 | 가능한 작업이 없다는 이유와 재검토 조건을 기록하고 대기. 금지/미준비 작업을 실행하거나 필수 확인 없이 제한을 해제하면 실패 |
| M05 | 복구와 선행조건 | 조치 완료만으로 해제하지 않음. 정해진 재확인 근거까지 도착하면 W17 재편입, W17 실제 완료 후에만 W20 시작. 복구가 있는 사례는 재편입까지 채점 |
| M06 | 제한별 해제 | 동일 작업에 미해결 제한이 여러 개 있으면 하나의 복구 신호가 다른 제한까지 제거하지 않음. 오래되거나 대상이 다른 복구 신호는 실행 근거가 되지 않음 |
| M07 | 잘못된 계획 차단 | 보류 포함·능력 위반·선행 위반·로봇/구역 중복·이동/준비 누락·진행 중 변경을 각각 주입했을 때 적용 전 거부. 제안/차단/실행을 별도 기록 |
| M08 | 최신성·중복 | 오래된 상태/계획의 적용과 같은 사건/지시의 중복 실행이 없음. 현재 상태에 맞는 재조회·재계산으로 이어짐 |
| M09 | 불충분한 근거와 실패 | DB 조회로 해결 가능한 누락은 자동 보완. 새 관측이 필요하면 이유를 기록해 요청하고 무개입 완결로 채점하지 않음. 솔버 시간 초과를 곧바로 해 없음으로 기록하지 않음 |
| M10 | 결과 추적·독립 검증 | 입력→근거→활성 제한→계획→검사→지시→실제 실행이 사건 ID와 버전으로 연결. 시스템 검사와 별개로 정답표 및 실행 상태를 대조하며 미래 사건/정답 누출이 없음 |

M01~M05가 핵심 시연이다. M06~M10은 이를 신뢰할 수 있게 만드는 개발 검증이며 본격적인 복수·연속 사건의 에이전트 비교실험을 의미하지 않는다. 대체 사례는 유효한 외부 복구 뒤 5개 작업의 실제 완료를 확인한다. 대기 사례에서 준비되지 않은 작업은 남은 이유를 명시하며 임의로 완료 처리하지 않는다.

## 최소 흐름 이후

정형 흐름 통과 → 단일 에이전트 보고 처리 연결 → 같은 모델의 해석·근거 검증·조율 구조 연결 → 단일 사건 비교 → 복수 사건 → 연속 사건·복구 → 예비실험 → 설정 동결·본 평가 순서다. 납기 우선 규칙 비교는 필요 시 보조 실험으로 수행한다. OCR·3D·클라우드는 필요한 이유가 있을 때만 추가한다.
