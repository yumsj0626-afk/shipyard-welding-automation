# 다음 구현 작업과 완료 기준

**현재 단계: 최소 구현용 기술 선택·아키텍처·데이터 계약 작성 완료, 애플리케이션 구현 미착수.** [DEC-01–06](decisions.md)의 개발용 결정과 [아키텍처](architecture.md), [데이터 계약](data-contracts.md)을 다음 구현의 기준으로 사용한다. 문서 작성이나 선택 확인용 작은 실행은 기능 구현·M01–M10 통과·연구 성과를 뜻하지 않는다. 실제로 수행한 확인 범위는 결정 기록을 따른다.

다음 작업의 목표는 **하나의 프로그램에서 로봇 2대·작업 5개의 정형 사건을 근거 확인 → 보류 → 대체 또는 대기 → 재계획 → 독립 검사 → 적용 → 시뮬레이션 → 복구와 재편입까지 연결**하는 것이다. 정형 경로에는 LLM·API 서버·웹 UI가 필요하지 않다.

M01–M05가 핵심 시연이다. M06–M10은 이를 신뢰할 수 있게 만드는 개발 검증이다. 대체 사례 D01에서는 유효한 외부 복구 뒤 5개 작업의 실제 완료를 확인한다. 대기 사례 D02에서 준비되지 않은 W19·W21은 미완료 이유를 남기고 임의로 완료 처리하지 않는다. 유효한 일정은 여러 개일 수 있으므로 W19를 반드시 특정 로봇에 배정하도록 강제하지 않는다.

수락 증거에는 실행 명령, 코드/환경/정책/입력 버전, 사례 ID, 테스트 결과와 해당 추적 기록을 연결한다. 실패를 숨기거나 아직 실행하지 않은 항목을 통과로 표시하지 않는다. 선택 확인용 작은 예제의 성공을 전체 흐름 성공으로 옮겨 적지 않는다.

## 최소 흐름 이후

정형 흐름 통과 → 단일 에이전트 문장형 보고 처리 → 같은 모델의 해석·근거 검증·조율 구성 → 단일 사건 비교 → 복수 사건 → 연속 사건과 복구 → 예비실험 → 설정 동결과 본 평가 순서다. 두 에이전트 구성은 같은 솔버·근거 조회·상태 갱신·검사·적용 경로를 사용한다. 역할 분리의 우수성을 전제하지 않는다.

본 평가의 사례 수·반복 수·시간 제한·수치 통과 기준은 예비실험 후 결정한다. 개발용 시간 제한이나 D01–D04의 값으로 본 평가 조건을 확정하지 않는다. 주 성과는 전체 평가 사건의 무개입 정답완결이며 생산 지연은 보조 지표다. 납기 우선 규칙 비교는 필요할 때 보조 실험으로 수행한다. OCR·3D·클라우드는 핵심 흐름에서 필요한 이유가 생겼을 때 검토한다.
